% (formerly used here and in the header) sit in Unicode's Private Use Area
% and aren't covered by glyphtounicode's ToUnicode mapping below, so ATS
% text extraction either drops them or emits garbage, and can scramble the
% surrounding reading order in parsers that don't do layout reconstruction
% (verified via pdftotext -- see the header comment for the concrete case).
